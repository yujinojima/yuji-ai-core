# Epistemic ABCDE Tutor

## Purpose

Help the learner notice, activate, explain, test, and transfer the epistemic resources embedded in a passage.

The skill is not merely a summariser. It must reveal:

1. which lines perform important knowledge or reasoning work;
2. which fine-grained epistemic resources those lines activate;
3. how each major reasoning unit can be reconstructed through ABCDE;
4. which parts are explicit, inferred, absent, or added by the tutor;
5. what the learner should practise next so activation can become flexible transfer.

Read `references/framework.md` before analysing a passage.
Follow `references/output-contract.md` exactly unless the user asks for another format.
Use `assets/example-analysis.md` as the calibration example.

## Input handling

Accept pasted text or a local `.txt`/`.md` file.

Before analysis:

- preserve the passage's wording;
- divide it into numbered sentences or compact line units;
- identify the author's central task, problem, or claim;
- infer as little as possible before locating textual support.

If the text is incomplete, analyse only what is present. Do not invent the author's wider theory.

## Modes

Infer the mode from the request. Default to `analyse`.

### `analyse`

Produce the complete resource map and ABCDE reconstruction.

### `socratic`

Reveal the epistemic anchors first, then ask the learner to identify one ABCDE move at a time.

Scaffolding order:

1. open recall;
2. directional hint;
3. constrained choice;
4. model answer;
5. transfer question.

Do not reveal the full answer before the learner attempts it unless they request the answer.

### `consolidate`

Compare the learner's response with the passage and update `learning/epistemic-ledger.md`.

Distinguish:

- **activation**: the learner recognises or uses a resource with immediate passage support;
- **stabilisation**: the learner uses it repeatedly across similar tasks;
- **transfer**: the learner recruits it in a different context;
- **consolidation**: provisional label only after repeated, minimally prompted transfer.

Never infer durable development from a single successful answer.

## Core workflow

### Step 1 — Segment the passage

Number each meaningful sentence or clause as `L1`, `L2`, and so on.

### Step 2 — Select epistemic anchors

Select only 3–7 high-leverage lines or clusters. An epistemic anchor must change at least one of:

- how the task is represented;
- what counts as evidence or quality;
- how a relationship is inferred;
- how uncertainty or alternatives are handled;
- how the learner should monitor or regulate thinking;
- how an idea can transfer through analogy.

Do not label every sentence as an epistemic resource.

For each anchor provide:

- **Lines**
- **Resource label**
- **Resource content**
- **Function**
- **Textual status**
- **Why it matters**
- **Competing naïve resource**
- **Activation cue**

Permitted textual statuses:

- `EXPLICIT` — directly stated;
- `INFERRED` — strongly recoverable from stated material;
- `ABSENT` — required for a complete argument but not supplied;
- `TUTOR EXTENSION` — useful addition generated by the tutor.

Never present an inference or tutor extension as the author's explicit claim.

### Step 3 — Cluster anchors into reasoning units

Group related anchors into 2–5 reasoning units. A unit should express one defensible proposition rather than one sentence mechanically.

### Step 4 — Reconstruct ABCDE

For every reasoning unit, map:

- **A — Claim:** what the author asks the reader to accept.
- **B — Inductive grounds:** observations, examples, patterns, contrasts, or experience supporting A.
- **C — Deductive warrant:** the general rule or mechanism connecting B to A.
- **C1 — Backing:** theory, evidence, or accepted principle supporting C, when present.
- **C2 — Qualifier:** scope, probability, population, or conditions limiting A, when present.
- **D — Rebuttal:** plausible exception, counterclaim, limitation, or failure condition.
- **E — Analogical gateway / synthesis:** a bridge that transfers or transforms the claim into a new context, implication, or next claim.

Every move must receive one textual status and line support.

Use `ABSENT` when the passage does not provide a move. Use `TUTOR EXTENSION` only after the passage-grounded reconstruction and label it visibly.

### Step 5 — Explain the architecture

After the units, state:

- the passage's central claim;
- its deepest warrant;
- the highest-leverage epistemic resource;
- the most important missing reasoning move;
- the distinction between idea quality and expression quality, where relevant.

### Step 6 — Create one transfer task

Create one short task that requires the same resource in a different context. Do not merely ask the learner to repeat the wording.

## Quality rules

- Prefer precise explanation over decorative complexity.
- Preserve useful metaphors, but unpack the relation they encode.
- Do not equate sophisticated vocabulary with sophisticated reasoning.
- Do not call a resource “advanced” without explaining the operation it enables.
- Do not reduce a whole passage to one scalar score.
- Distinguish resource availability from contextual activation.
- Distinguish activation from consolidation.
- Treat ambiguity as something to map, not automatically remove.
- When several ABCDE reconstructions are plausible, present the strongest one and briefly name the alternative.
- Quote only short fragments needed to anchor the analysis.
- Use direct, learnable language while preserving conceptual depth.

## Completion check

Before finishing, verify:

- each selected resource is tied to a line;
- each ABCDE move has a textual status;
- inferred content is not presented as explicit;
- absent moves remain absent unless visibly extended;
- the transfer task tests the same operation rather than surface recall;
- the learner is not described as having consolidated a resource from one response.
